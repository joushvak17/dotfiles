# Dotfiles

Personal dotfiles, managed with GNU Stow. Each top-level folder is one stow
package whose contents mirror `$HOME`:

| Package    | Files in repo                          | Lands at                     |
|------------|----------------------------------------|------------------------------|
| `fish`     | `fish/.config/fish/config.fish`        | `~/.config/fish/`            |
| `git`      | `git/.gitconfig`                       | `~/.gitconfig`               |
| `kitty`    | `kitty/.config/kitty/{kitty.conf,current-theme.conf}` | `~/.config/kitty/` |
| `nvim`     | `nvim/.config/nvim/`                   | `~/.config/nvim/`            |
| `starship` | `starship/.config/starship.toml`       | `~/.config/starship.toml`    |
| `tmux`     | `tmux/.tmux.conf`                      | `~/.tmux.conf`               |

- Always edit files in this repo, never the symlink targets in `$HOME`.
- Applying a package is `stow <pkg>` from the repo root. It writes outside the
  repo, so ask before running it.
- New tool → new top-level package folder with the same mirrored layout.

## Theme

Current theme: **Kanagawa Wave**. A theme switch must touch every one of these:

1. `kitty/.config/kitty/current-theme.conf`: the full palette. The block between
   `BEGIN_KITTY_THEME`/`END_KITTY_THEME` in `kitty.conf` is managed by
   `kitty +kitten themes`; keep that structure.
2. `nvim/.config/nvim/lua/plugins/colorscheme.lua`: plugin, setup and `colorscheme`.
   `plugins/lualine.lua` sets `theme = "kanagawa"`; update it too if the plugin changes.
3. `tmux/.tmux.conf`: only the `# Colors` block of `%hidden` variables
   (BG, BG_ALT, FG, MUTED, BORDER, ACCENT, HIGHLIGHT). Nothing else in the file
   should hold a hex code. `%hidden` needs tmux ≥ 3.1.
4. `starship/.config/starship.toml`: the `palette = ...` line and its `[palettes.*]` table.
5. `fish/.config/fish/config.fish`: the `# Palette` `set -l` block; it also feeds
   `FZF_DEFAULT_OPTS`.

Take hex values from the kitty theme file so all tools agree, and map colours
by role/hue (bg→bg, green accent→green accent), not by position.

Past theme commits said "across all configs" but missed tmux, and
**starship + fish are still on Kanagawa Dragon** (`#c5c9c5`, `#87a987`, …),
not Wave. Fix those the next time the theme is touched.

## Verifying changes

Check a config before reporting it done, without touching the live session:

- **tmux**: start a throwaway server on a scratch socket, then query it one
  option per `show` call (`show` takes at most one option name):
  ```
  tmux -S <scratch>/test.sock -f tmux/.tmux.conf new -d
  tmux -S <scratch>/test.sock show -g status-style
  tmux -S <scratch>/test.sock kill-server
  ```
- **fish**: `fish -n fish/.config/fish/config.fish`
- **nvim**: `nvim --headless +qa` should exit without errors
- **kitty**: `kitty --debug-config`

Reload in a live session: tmux `C-a r` (prefix is `C-a`), fish `exec fish`.

## Git workflow

- Branch: `master`, pushed to `origin/master`. Commit or push only when asked.
- Commit messages: short imperative subject naming the config, matching history:
  `Change theme to kanagawa wave across all configs`,
  `Add opacity in kitty config`, `Fix rust lsp issue in nvim config`.
- The user sometimes amends and force-pushes their own commits. If a commit
  hash changes between steps, re-check `git log` rather than assuming
  something went wrong.
- `nvim/.config/nvim/lazy-lock.json` changes whenever plugins update. Leave it
  out of unrelated commits unless told otherwise.

## Don't "fix" these

- `fish/config.fish` conda block (`>>> conda initialize >>>`) is generated by
  `conda init` and has machine-specific paths; leave it as is.
- `git/.gitconfig` blank `helper =` lines before `!gh auth git-credential` are
  intentional (they reset inherited helpers).
- Keybinding layers are deliberately separate: kitty uses a `ctrl+g` prefix,
  tmux uses `C-a`, and `C-h/j/k/l` is shared between tmux and nvim via
  vim-tmux-navigator (`plugins/tmux-navigator.lua` + the `is_vim` block in tmux).

## Neovim layout

- `init.lua` only requires `config.lazy` (lazy.nvim bootstrap).
- `lua/config/`: options, keymaps, autocmds, lazy setup.
- `lua/plugins/`: one file per plugin spec.
- `lua/servers/`: one file per LSP server, wired up from `servers/init.lua`.
  Rust is handled by `plugins/rustaceanvim.lua`, not lspconfig.
- `lua/utils/`: LSP and diagnostics helpers.
